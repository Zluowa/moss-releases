Moss · 本机工作区

一条任务线。运行时还是你已经登录的那一侧。账号与托管模型路由是第二层，不是九个产品名。

运行时两层

围在外面，不换掉你已经登录的运行时。

编码代理继续用它自己的登录态、模型、工具和权限。Moss 只把工作收进同一条任务线，并在你选择的账号与托管模型之间指路。

本机已登录的编码代理运行时

运行时

接上本机已经装好、已经登录的编码代理。认证、配额、工具和会话语义仍由那个运行时负责。

账号与托管模型路由

路由

当你选用账号或托管模型通路时，Moss 只做选择与指路。提示、文件和命令结果仍发往你选中的那一侧。

耐久的任务归属

一个工作区。分开的任务。

编码代理只是工作的一部分。目标、会话、工作目录、活着的过程和交付状态钉在同一件任务上。

一件任务占一条线

目标、运行时会话、工作目录和交付状态跟着同一件任务走，而不是搅进一条总线程。

两层可换，不迁账号

01 / 归属

一件任务占一条线

目标、运行时会话、工作目录和交付状态跟着同一件任务走。结果先看再收，而不是把无关工作搅进一条总线程。

同一条线
  • 目标一件事，一条任务
  • 运行时本机已登录的那一侧
  • 结果先核对，再收下

02 / 并行

并行时彼此分开

同时做几件事时，每条线有自己的归属。需要隔离改动时，用各自的 Git 工作树，避免互相覆盖。

分开的边界
  • 任务 A自己的目录与状态
  • 任务 B自己的工作树
  • 复核看得出是哪一件

从目标到证据

执行和核对留在同一圈里。

指挥几件任务、把同一件工作交给另一侧、盯着还在跑的进程、核对这些改动是否真的成立——都不必先问「这是哪一件事」。

03 / 归属

先看清这条线是谁的

一件目标对应一件任务。会话、运行时和环境跟任务走，而不是把无关工作叠进同一条对话。

谁在做这件事
  • 任务一条可见的工作线
  • 会话跟任务走，不混线
  • 状态还挂在这件目标上

04 / handoff

同一件任务可以换一侧继续

换运行时或路由时，任务环境和 Moss 往前递的上下文还在。交接前后都要看工作树，因为两侧工具并不相同。

换一侧
  • 从本机已登录的运行时
  • 到账号与托管模型路由
  • 仍是同一件任务

05 / 现场进程

长任务仍挂在这件事上

开发服务器、测试看守和一次性命令跟启动它们的任务在一起，而不是散落在无名终端里。

还在跑
  • 进程开发服务器 / 测试看守
  • 归属启动它的那件任务
  • 位置不进无名终端

06 / 核验

看行为，不只看差异

差异、命令输出和检查结果回到同一件任务。先核对再交付，而不是在另一个工具里重装上下文。

先看再收
  • 差异还在这件任务上
  • 输出命令与检查结果
  • 决定核对之后再交付

本机优先的边界

每一部分工作去哪里，应当能说清楚。

Moss 把工作区层留在这台机器上，再连到你选中的运行时。边界是明确的：本地状态不出门，提供商流量只去你选的那一侧。

工作区状态在本机

项目、任务历史、设置和桌面端状态由这台机器上的应用保存，而不是一份 Moss 托管工作区账号。

流量去你选中的运行时

提示、文件、差异、命令输出和工具结果发给这次选中的编码代理或路由目标。Moss 不把常规提供商流量转成自己的模型服务。

装上桌面端，使用机器上已经登录的提供商账号即可开始。不必先注册一份 Moss 云账号。

产品边界

先弄清 Moss 管什么，再开始跑任务。

模型套餐、本机数据、未签名安装包、Git，以及已经在机器上的提供商账号，各自停在哪。

Moss 是什么？

Moss 是本机优先的桌面工作区。它围在已经登录的编码代理运行时外面，并提供账号与托管模型路由，而不替换这些运行时。一件任务占一条工作线。

要不要再买一份 Moss 模型套餐？

不用。Moss 不出售额外的模型计划。你使用机器上已经登录的编码代理，或你选择的账号与托管模型通路。

数据是不是本机优先？

是。工作区状态留在这台机器上。发往提供商的内容只去你选中的运行时。开始使用不需要 Moss 云账号。

为什么安装包标了「未签名」？

0.7.2 内测包没有 Apple 公证，也没有 Authenticode。打开步骤见 /moss-releases/install/。本页不提供签名版。

Git 怎么接进去？

按普通分支或隔离工作树做事，在同一件任务里看差异、跑该跑的检查。并行任务需要各写各的目录时，用分开的工作树。

本机已经有的提供商账号够不够？

够用来开始。先让编码代理运行时在终端里能独立工作，再在 Moss 里选用它。账号与托管模型路由是第二层。
