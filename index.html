提供商可携

Moss 围在外面，不换掉你已经登录的运行时。

编码代理继续用它自己的登录态、模型、工具和权限。Moss 只把工作收进同一条任务线，并在你选择的账号与托管模型之间指路。

已登录的编码代理运行时 账号 / 托管模型路由 不替换这些运行时

运行时层

接上本机已经装好、已经登录的编码代理。认证、配额、工具和会话语义仍由那个运行时负责。Moss 不要求你把工作迁进另一个厂商账号。

路由层

当你选用账号或托管模型通路时，Moss 只做选择与指路。提示、文件和命令结果仍发往你选中的那一侧，而不是先经过一份 Moss 模型套餐。

耐久的任务归属

一件任务，一条工作线。

目标、会话、工作目录、活着的过程和交付状态钉在同一件任务上。并行时彼此分开，结果先看再收。

一件事不搅进另一件

打开任务时就确定这条线归谁。对话、目录和状态跟着任务走，而不是混进一条总线程。

并行也能看清边界

同时做几件事时，每条线有自己的归属。需要隔离改动时，用各自的 Git 工作树，避免互相覆盖。

结果可以复核

命令、文件改动、差异和检查都还挂在这件任务上。先看清楚，再决定收下、改回去或交给下一侧。

仓库可接着做

每个仓库都保持能继续的状态。

产品、客户仓和试验仓不必拆成一堆窗口再重讲一遍。每个仓库自己的任务、运行时会话和环境都留在本机，下次打开还能接着做。

换仓不丢线

离开一个仓库时，任务目标和最近活动还在。回到这个仓，不用从零拼上下文。

仓和任务分开记账

仓库是工作发生的地方，任务是这条工作线的归属。两者都在本机，不依赖 Moss 云工作区账号。

从目标到证据

执行和核对留在同一圈里。

指挥几件任务、把同一件工作交给另一侧、盯着还在跑的进程、核对这些改动是否真的成立——都不必先问「这是哪一件事」。

03 / 活着的进程

开发服务器、测试看守和一次性命令跟启动它们的任务在一起，而不是散落在无名终端里。

04 / 核对

看行为，不只看差异

差异、命令输出和检查结果回到同一件任务。先核对再交付，而不是在另一个工具里重装上下文。

产品边界

先弄清 Moss 管什么，再开始跑任务。

模型套餐、本机数据、未签名安装包、Git，以及已经在机器上的提供商账号，各自停在哪。

Moss 是什么？

Moss 是本机优先的桌面工作区。它围在已经登录的编码代理运行时外面，并提供账号/托管模型路由，而不替换这些运行时。一件任务占一条工作线：目标、会话、过程和核对都留在同一处。

要不要再买一份 Moss 模型套餐？

不用。Moss 不出售额外的模型计划。你使用机器上已经登录的编码代理，或你选择的账号/托管模型通路。额度、模型和权限仍归那一侧。

数据是不是本机优先？

是。工作区状态留在这台机器上。发往提供商的内容只去你选中的运行时。开始使用不需要 Moss 云账号。

为什么安装包标了「未签名」？

0.7.2 内测包没有 Apple 公证，也没有 Authenticode。Gatekeeper 和 SmartScreen 会拦截，这是预期行为。打开步骤见 /moss-releases/install/。本页不提供签名版，也不假装有签名版。

Git 怎么接进去？

按普通分支或隔离工作树做事，在同一件任务里看差异、跑该跑的检查、提交打算留下的改动。并行任务需要各写各的目录时，用分开的工作树，避免互相覆盖。

本机已经有的提供商账号够不够？

够用来开始。先让编码代理运行时在终端里能独立工作，再在 Moss 里选用它。账号/托管模型路由是第二层，不是把你已有的登录态作废。

未合并的改动算不算已经发布？

不算。本页只描述当前公开站点和发布仓里能核对的产品边界。未合并的 Pull Request 不是已发布能力。
